# Glossary

Terms used across multiple ADRs without inline definition.

## Wire protocol & content

| Term | Definition |
| --- | --- |
| **Blob** | A content-addressed byte sequence identified by its BLAKE3 hash. |
| **Chunk** | The BLAKE3 hash-tree leaf size (1024 bytes). iroh-blobs uses this for verified streaming — see [ADR 002](002-content-addressing.md#adr-002-content-addressing) for the addressing scheme. |
| **Hash sequence** | An ordered collection of blob hashes (iroh's equivalent of a directory/manifest). |
| **Namespace** | A publisher-owned `uint256` identifier for a content set and the unit of origin addressing: a `cdn/client/v1` request can pair a blob hash with a namespace its content is published under, and the DAO authorizes an origin operator set per namespace (so redundancy is a namespace-level property). A node serves and advertises a hash only while it holds a live origin attestation for it, signed by an operator seated in the namespace that the attestation names. `namespaceId == 0` is not a namespace: it holds no seats and attests nothing. On a request it means the requester does not name one, and the node finds the content through the DHT and its origin attestations. See [ADR 002 § Publisher Identity and Namespaces](002-content-addressing.md#publisher-identity-and-namespaces). |
| **Publisher** | An Ethereum address that owns at least one namespace in `PublisherRegistry`; status is acquired implicitly on the first `createNamespace()` call, with no separate registration step. Once governance has vetted the publisher wallet, that publisher seats and unseats the origin operators for its own namespaces directly ([ADR 011 § Origin Assignment Authority](011-content-takedown.md#origin-assignment-authority)). See [ADR 002 § Publisher Identity and Namespaces](002-content-addressing.md#publisher-identity-and-namespaces). |
| **NodeId** | An iroh public-key identifier; the on-wire identity of a node. Bound to an Ethereum address on-chain via EIP-712 signature in `CapacityBond.registerNode` ([ADR 001](001-network.md#adr-001-network-topology-and-peer-mesh)). |
| **Node** | A staked participant that caches and serves blobs. Some nodes are configured with an origin backend; others are pure caches. |
| **Client** | A lightweight QUIC endpoint that streams content and pays per MB. |
| **Discovery open** | A `cdn/client/v1` stream that a requester opens with no voucher, to learn a node's signed quote, proven size and coverage. The requester pays on the stream of the node it picks and cancels the others — see [ADR 005 § Discovery opens](005-protocol.md#discovery-opens). |
| **Origin-backed node** | A node configured with an S3-compatible object store (S3/R2/B2/MinIO), NFS mount, or local disk. Can serve any blob in that store, never experiences a true cache miss. |
| **Origin attestation** | A seated origin's signed, expiring statement that it serves a hash in a namespace: the EIP-712 `OriginAttestation(hash, namespaceId, timestampUs, ttlSec)`. The origin picks the TTL (1 h to 24 h). Every DHT record carries one, and a node serves a hash only while it holds a live one. A relay keeps the attestation from its pull leg, forwards it in every `ok: true` answer and refreshes it before it expires. See [ADR 022 § Origin Attestation](022-content-discovery.md#origin-attestation). |
| **ALPN** | Application-Layer Protocol Negotiation — identifies which protocol a QUIC connection uses (e.g., `cdn/client/v1`, `cdn/dht/v1`). |

## Payments

| Term | Definition |
| --- | --- |
| **Payment token** | The dual-currency model's settlement asset: the currency clients pay in and operators are paid in. The concrete asset is **USDC**, fixed at contract deployment (immutable, 6 decimals) — see [ADR 003](003-payments.md#adr-003-payment-model). This is the canonical term used throughout the spec for the pool-deposit, voucher, and fee-distribution currency; "USDC" appears only where a USDC-specific property is load-bearing (decimals, Circle counterparty risk, on-chain identifiers, swap pairs, dollar-denominated constants). |
| **Governance token** | The dual-currency model's bonding/governance asset. The concrete asset is **TOKEN**, the protocol's native fixed-supply (1B) `ERC20Burnable` — see [ADR 026](026-tokenomics.md#adr-026-tokenomics). "TOKEN" is used as the asset symbol/unit; "governance token" is the role term. Distinct from the payment token; never interchangeable. |
| **Pool** | One funded on-chain deposit (the `PaymentPool` escrow) that backs off-chain vouchers from many capped signers to many nodes. Three roles: the **owner** funds it, signs capabilities, and receives the reclaim; a **signer** authorizes vouchers up to a capped, expiring capability; a **provider** (node) delivers and redeems its own vouchers. Lives on a payment chain, with immutable parameters and no governance. Funded with the payment token; the owner closes and reclaims the unspent remainder after a grace window — see [ADR 003](003-payments.md#adr-003-payment-model). Identified by `poolId = keccak256(owner, poolNonce)`. |
| **Capability** | An off-chain, owner-signed authorization delegating a signer: `{signer, spending_cap, pool_id, expiry}`. Node-agnostic (valid at every node), registered on-chain once on the signer's first redemption. Bounds the signer to its `spending_cap` and retires it at `expiry` — see [ADR 003](003-payments.md#adr-003-payment-model). |
| **Voucher** | A signed off-chain payment message. The EIP-712 signed fields are `{poolId, signer, provider, amount, bytesDelivered, chainRoot, chunkPrice}` (`provider` names the payee node), carried on the wire alongside the signature. `amount` is the cumulative settlement anchor; `chainRoot` heads an optional hash chain that advances it between signatures, and a `chainRoot` of zero seals the voucher at exactly `amount` (see [ADR 003](003-payments.md#hash-chain-metering-payword)). The contract settles in a single token fixed at deployment, so the voucher carries no token field; the EIP-712 domain separator binds it to the one contract deployment. Node-addressed and valid only under the signature of its capability-authorized signer. The bearer instrument for per-MB payments. |
| **Chain root / preimage** | The hash chain that meters delivery between signatures ([PayWord](003-payments.md#hash-chain-metering-payword)). The payer commits `chain_root = keccak^255(seed)` in a voucher and releases `keccak^(255−k)(seed)` after chunk `k`. A released **preimage** is an unsigned bearer proof: it proves its own index by hashing forward to the root, costs one keccak to verify, and is worth nothing outside the lane whose voucher names its root. Redemption resolves `claimed = amount + chain_index × chunk_price`. |
| **Payment chunk** | The payment quantum, `chunk_bytes` = 1 MiB — the price quantum, the meter tick, and the withholding bound at once. A protocol constant, sized by USDC's 6-decimal payability floor ([ADR 003](003-payments.md#chunk-sizing-and-the-payability-floor)). Distinct from **Chunk** above, which is the 1024-byte BLAKE3 hash-tree leaf. |
| **TOKEN** | The concrete governance token: the protocol's native fixed-supply (1B) ERC-20. Used for capacity bonding and governance — see [ADR 026](026-tokenomics.md#adr-026-tokenomics). There is no ongoing TOKEN-denominated service emission; year-1 operator bootstrap is funded by off-chain USDC infrastructure subsidies per [ADR 026 § Bootstrap mechanism — pre-seed USDC](026-tokenomics.md#bootstrap-mechanism--pre-seed-usdc). |
| **USDC** | The concrete payment token: native 6-decimal USDC on each payment chain, one immutable address per pool deployment. All pool deposits, sweeps, and the externally-raised pre-seed pool are USDC-denominated — see [ADR 003](003-payments.md#adr-003-payment-model), [ADR 026](026-tokenomics.md#adr-026-tokenomics). |
| **Governance chain** | Ethereum L1. Holds TOKEN, bond, governance, treasury, and buyback — see [ADR 016 § Deployment Tiers](016-contract-interactions.md#deployment-tiers). |
| **Payment chain** | Any EVM chain with native 6-decimal USDC, Circle CCTP V2 with hooks, and a censorship window below the pool's `disputeWindow`. Holds only `PaymentPool` and USDC. Many payment chains run at the same time — see [Appendix: Governance Chain and Payment Chain Admission](appendix-l2-deployment.md#appendix-governance-chain-and-payment-chain-admission). |
| **Sweep** | The bridge message from a payment chain to the governance chain (CCTP burn-and-mint in the reference deployment). It carries the protocol share (USDC) and the served bytes of up to 32 operators together; a bridge adapter receives it and calls `FeeRouter.deposit` once per operator. |
| **Bridge adapter** | A stateless governance-chain contract that receives sweeps from one bridge and calls `FeeRouter.deposit` for each operator with its part of the USDC that arrived. `CctpSweepReceiver` is the CCTP V2 adapter. Anyone may deploy one; `FeeRouter` trusts none of them. |
| **Bytes feed** | The served-bytes records `(operator, bytes, amount)` in a sweep's hook data, one per operator. It is the only path by which served bytes reach the governance chain. |
| **Protocol share** | The part of each redemption that the operator does not receive on the payment chain. It accrues in the pool as pending and leaves in a sweep. |

## Tokenomics & incentives

| Term | Definition |
| --- | --- |
| **Bond** | TOKEN deposited in `CapacityBond` proportional to declared bandwidth capacity: `bond = k × Mbps^α` (defaults `k=12.6`, `α=1.2`). The only TOKEN-side requirement on operators. At entry, the bond must also meet the global `minBond` floor — see [ADR 026 § Capacity-bond curve](026-tokenomics.md#capacity-bond-curve) and [§ Minimum bond is non-retroactive](026-tokenomics.md#minimum-bond-is-non-retroactive). |
| **CapacityBond** | The capacity-bonded operator-registry contract on the governance chain. Holds TOKEN bond, enforces `bond ≥ bond_required(declared_capacity)`, manages the NodeId↔Ethereum-address binding — see [ADR 026](026-tokenomics.md#adr-026-tokenomics) and [ADR 016 § Contract Inventory](016-contract-interactions.md#contract-inventory). |
| **App Incentives** | A 19%-of-supply (190M TOKEN) demand-side ecosystem bucket, Treasury-multisig administered; 20% unlocked at TGE, then 48-month linear. Funds publisher rebates and integration grants — see [ADR 026 § App Incentives](026-tokenomics.md#app-incentives). |
| **`windowEpochs`** | The governable trailing-window size (in epochs) used by `FeeRouter.bytesInWindow` (vote-weight numerator). Default 13 (~1 quarter at 1-week epochs); bounds `[4, 26]` — see [ADR 036 § Governable parameters with safety bounds](036-served-bytes-voting-weight.md#governable-parameters-with-safety-bounds). |
| **Served-bytes voting weight** | The governance vote-weight source under [ADR 036](036-served-bytes-voting-weight.md#adr-036-served-bytes-voting-weight): `vote_weight(op, t) = min(served_bytes_window(op, t), voteCapBps × total_bytes_window(t) / 10_000) × age_ramp(op, t)`, where `served_bytes_window(op, t)` is the trailing-`windowEpochs` sum of `FeeRouter.bytesPerEpoch[op]`. `FeeRouter.bytesPerEpoch` is governance-canonical. |
| **Epoch** | The 1-week trailing-window unit. Per-operator served-bytes credits accumulate on the governance-chain `FeeRouter`, stamped to the epoch of the sweep's arrival block, and feed the served-bytes voting weight ([ADR 036](036-served-bytes-voting-weight.md#adr-036-served-bytes-voting-weight)). A late sweep never changes a closed epoch. |
| **FeeRouter** | The governance-chain receiver of sweeps, through its permissionless `deposit`. It credits the operator's bytes, splits the USDC into a rebate to the operator, a buyback share, and a treasury remainder, and serves the vote-weight reads — see [ADR 026 § FeeRouter split](026-tokenomics.md#feerouter-split). Its per-operator bytes accounting is the governance vote-weight source per [ADR 036](036-served-bytes-voting-weight.md#adr-036-served-bytes-voting-weight). |

## On-chain enforcement

| Term | Definition |
| --- | --- |
| **`CapacityBond`** | The capacity-bonded operator-registry contract on the governance chain. Holds TOKEN bond, enforces `bond ≥ bond_required(declared_capacity)` via the lock-to-capacity curve `bond = k × Mbps^α`, manages the NodeId↔Ethereum-address binding, and holds the EIP-712 domain that operator signatures use ([ADR 005 § Signer binding](005-protocol.md#signer-binding)). |
| **`BuybackBurner`** | The governance-chain contract that `FeeRouter` feeds with the buyback share of each sweep. Governance turns the buyback on by setting `buybackBps` above 0 and the burner address. It swaps that USDC into TOKEN via a Uniswap V3 50/50 pool and burns the proceeds — see [ADR 003 § BuybackBurner](003-payments.md#buybackburner) and [ADR 018](018-liquidity-strategy.md#adr-018-liquidity-strategy-uniswap-v3-5050-pol). |
| **`PublisherRegistry`** | The on-chain registry of namespace ownership and lifecycle (create, transfer under timelock). Records who owns each namespace and stores no content hashes — the hash→namespace association is supplied off-chain by the requester at fetch time. See [ADR 002 § Contract: PublisherRegistry](002-content-addressing.md#contract-publisherregistry) and [ADR 016 § Contract Inventory](016-contract-interactions.md#contract-inventory). |
| **`OriginAssignment`** | The DAO's positive origin-authority contract: governance vets a publisher wallet once, after which that publisher seats and unseats origin operators for its own namespaces instantly. `namespaceId == 0` has no authorized origins. Cache-only serving stays permissionless; only the origin role is gated here. See [ADR 011 § Origin Assignment Authority](011-content-takedown.md#origin-assignment-authority). |
| **StreamResponse signature** | The EIP-712 secp256k1 signature (`operator_sig`) on every `StreamResponse`, made with the operator's Ethereum key under the `CapacityBond` domain. A verifier recovers it with `ecrecover` to attribute the answer to the node's operator — see [ADR 005 § Signer binding](005-protocol.md#signer-binding). |
